# v0.8.0 - Multi-Tab System

**Status:** Planned (starts after v0.7.0 release)
**Target Release:** TBD
**Branch:** `v0.8.0-dev` (to be created)

## Overview

This release transforms the SSH Profile Manager from a modal-based terminal UI to an app-level tabbed interface, similar to modern web browsers. This is a major architectural change that makes the embedded terminal a first-class feature with multi-tab support, pop-out windows, and efficient tab management.

**Focus:** Infrastructure and architecture for multi-tab terminal sessions
**Not in scope:** Terminal customization (color schemes, fonts, etc.) - moved to v0.9.0

## Key Architectural Changes

### From Modal to Tabs

**Before (v0.6.1):**
- Profile list is the main screen
- Terminal opens in a modal overlay
- Only one terminal session visible at a time
- Modal hides the profile list

**After (v0.8.0):**
- App-level tab bar with "Profiles" tab + Terminal tabs
- Profiles tab shows the profile list (always present, can't close)
- Each SSH connection opens in a new terminal tab
- Quick switching between profile list and active sessions
- Tabs can be popped out to separate windows

**Benefits:**
- Terminal as primary content (not hidden in modal)
- Familiar browser-like paradigm
- Multi-monitor support via pop-out windows
- Multiple sessions to different profiles OR same profile
- More productive workflow

## Features

### 1. App-Level Tab System

**Description:** Top-level tab bar that replaces the current header, supporting multiple terminal sessions alongside the profile list.

**User Stories:**
- As a user, I want to switch between my profile list and active terminal sessions using tabs
- As a user, I want to open multiple SSH connections simultaneously in different tabs
- As a user, I want to duplicate a connection to open multiple sessions to the same profile
- As a user, I want to pop out a terminal tab to a separate window for multi-monitor setups
- As a user, I want to reconnect a failed SSH session without closing the tab

---

#### Tab Types

**Profiles Tab:**
- Always present, leftmost position
- Cannot be closed
- Shows current profile list (existing main screen content)
- Becomes active when all terminal tabs are closed
- Becomes active when any terminal tab is closed

**Terminal Tabs:**
- One tab per SSH session
- Created when user clicks "Connect" (if embedded terminal is enabled in settings)
- Show profile name with subtle connection status color
- Can be closed, duplicated, popped out, or refreshed
- Independent SSH sessions (can have multiple tabs to same profile)

---

#### Tab UI Layout

**Top-Level Structure:**

```
+----------------------------------------------------+
| [Profiles] [prod-server ...×] [dev-db ...×]        |
+----------------------------------------------------+
| Content Area:                                      |
|  - Profiles tab: Profile list, search, groups, etc.|
|  - Terminal tab: xterm.js terminal session         |
+----------------------------------------------------+
```

**Individual Tab Structure:**
```
[profile-name] [...] [×]
```
- **Profile name** - Tab label, truncated if too long
- **... button** (meatball menu) - Dropdown with tab actions
- **× button** - Quick close (most common action)

**Profiles Tab:**
```
[Profiles]
```
- No close button or menu (permanent tab)
- Always leftmost position

---

#### Tab Actions

**Available in Meatball Menu (...):**

1. **Duplicate Tab**
   - Opens a new SSH session to the same profile in a new tab
   - Creates independent PTY session
   - Both tabs can be used simultaneously
   - Useful for running multiple commands on same server

2. **Pop Out to Window**
   - Moves the terminal tab to a separate Tauri window
   - Tab disappears from main window tab bar
   - New window shows terminal only (no Profiles tab, no tab bar)
   - Window title shows profile name
   - Useful for multi-monitor setups

3. **Pop In from Window** (shown in pop-out window only)
   - Returns the popped-out terminal to a tab in main window
   - Restores to tab bar (appended to right)
   - Session remains active, no reconnection needed

4. **Refresh Connection**
   - Disconnects and reconnects the SSH session
   - Keeps the tab open
   - Useful when connection dies or becomes unresponsive
   - Shows "Connecting..." state during reconnection

5. **Close Tab**
   - Same as clicking × button
   - Prompts for confirmation if connection is active
   - Terminates SSH session and removes tab

**Quick Actions:**

- **× button**: Close tab (prompts if connected)
- **Click tab**: Switch to that tab's content

---

#### Keyboard Shortcuts

**Tab Navigation:**
- **Cmd/Ctrl+Tab** - Switch to next tab (cycles right, wraps around)
- **Cmd/Ctrl+Shift+Tab** - Switch to previous tab (cycles left, wraps around)

**Tab Actions:**
- **Cmd/Ctrl+W** - Close active tab (prompts if connected)
- **Cmd/Ctrl+D** - Duplicate active terminal tab (no-op on Profiles tab)
- **Cmd/Ctrl+Shift+O** - Pop out active terminal tab (no-op on Profiles tab)
- **Cmd/Ctrl+R** - Refresh active terminal connection (no-op on Profiles tab)

**Note:** No Cmd+1-9 shortcuts (inconsistent with 10+ tabs)

---

#### Connection Status Colors

**Visual Indicator:**
- Subtle background tint on terminal tabs
- Uses same color tones as existing terminal status indicator
- Very low opacity/saturation (avoid rainbow effect with many tabs)

**Status Colors:**
- **Connected** - Subtle green tint (e.g., `background: rgba(34, 197, 94, 0.08)`)
- **Connecting** - Subtle yellow tint (e.g., `background: rgba(234, 179, 8, 0.08)`)
- **Error/Failed** - Subtle red tint (e.g., `background: rgba(239, 68, 68, 0.08)`)
- **Disconnected** - No tint (default gray background)

**Profiles tab** has no status color (always default).

---

#### Tab Behavior

**Opening Terminals:**
- User clicks "Connect" button on a profile (or recent connection)
- If terminal preference is "Embedded Terminal", open in new tab
- If terminal preference is "Native Terminal", open external terminal (no tab)
- New tab appears to the right of existing tabs
- New tab becomes active immediately
- Profiles tab remains in tab bar

**Closing Tabs:**
- Clicking × or using Cmd+W triggers close
- If connection is active, show confirmation dialog:
  - Title: "Close connection to [profile-name]?"
  - Message: "The SSH connection will be terminated."
  - Buttons: "Disconnect" (danger) / "Cancel"
- On confirm, terminate SSH session and remove tab
- After closing any terminal tab, switch to Profiles tab
- If closing a pop-out window with active connection, same confirmation prompt

**Tab Switching:**
- Clicking a tab makes it active
- Content area switches to that tab's view (Profiles content or Terminal)
- Active tab has distinct visual style (underline, background, etc.)
- Use CSS `display: none/block` to toggle views (don't destroy/recreate terminals)

**Duplicate Tab:**
- Creates new SSH session to the same profile
- Opens in new tab (appended to right)
- New tab becomes active
- Both sessions are independent (can run different commands)

**Pop Out:**
- Creates new Tauri window with terminal content only
- Window title: "SSH Profile Manager - [profile-name]"
- Window has no tab bar, no Profiles content
- Window shows terminal with a "Pop Back In" button in header
- Original tab disappears from main window
- If main window is closed, pop-out window closes too (terminates session with prompt)

**Pop In:**
- Click "Pop Back In" button in pop-out window
- Terminal moves back to main window as a tab
- Pop-out window closes
- New tab appears in main window (appended to right)
- Tab becomes active

**Refresh:**
- Disconnect current SSH session
- Show "Connecting..." status
- Reconnect to same profile
- Terminal clears and shows new session output
- Tab remains open, session ID changes

### 2. Tab Overflow & Scrolling

**Problem:**
When many terminal tabs are open, they can exceed the available horizontal space in the tab bar. Shrinking tabs to fit (like browsers do with 100+ tabs) makes them unreadable and defeats the purpose of showing the profile name.

**Solution:**
Maintain a minimum readable tab width and implement horizontal scrolling with keyboard and mouse navigation.

**User Stories:**
- As a user, I want tab labels to remain readable even with 10+ tabs open
- As a user, I want to navigate to hidden tabs using arrow keys
- As a user, I want to see visual indicators when there are tabs off-screen
- As a user, I want the active tab to automatically scroll into view

---

**Tab Width Constraints:**

- **Minimum width**: 150px (ensures profile name is readable)
- **Maximum width**: 200px (prevents very long names from dominating)
- **Ideal width**: 180px (fits ~4-5 tabs on 1024px screen)
- Tabs **never** shrink below minimum width

**Calculation:**
- Available space = Tab bar width - Logo/title width - Settings button width
- If (Number of tabs × 150px) > Available space → Enable scrolling

---

**Scrolling Behavior:**

**Mouse:**
- Horizontal scroll wheel on tab bar scrolls left/right
- Scrollbar appears at bottom of tab bar (thin, OS-native style)

**Keyboard:**
- **Arrow Left** - Scroll tab bar left (reveal tabs to the left)
- **Arrow Right** - Scroll tab bar right (reveal tabs to the right)
- Scrolls by 150px (one tab width) per press
- Smooth scroll animation (~200ms)

**Auto-scroll Active Tab:**
- When switching tabs (click or keyboard), active tab scrolls into view
- If active tab is partially/fully hidden, scroll to center it
- Smooth scroll animation (~200ms)

---

**Visual Indicators:**

**Gradient Fade (Primary Approach):**
- Left edge: Fade-out gradient when tabs are scrolled right (hidden tabs on left)
- Right edge: Fade-out gradient when more tabs exist on right
- Gradient: 20px wide, semi-transparent overlay
- Subtle, doesn't obscure tabs

**Design System Pattern:**
This horizontal scroll + gradient indicator pattern is reusable across the app:
- **Tab bar** - Primary use case
- **Recent connections bar** - Apply same overflow handling
- **Future horizontal lists** - Any component with horizontal overflow

Create reusable CSS classes and JavaScript utilities for this pattern to ensure consistency.

**JavaScript (Reusable Utilities):**
```javascript
// Reusable function for any horizontal scroll container
function updateScrollGradients(container) {
  const scrollWrapper = container.querySelector('.horizontal-scroll-wrapper') ||
                       container.querySelector('[class*="scroll-wrapper"]');
  const leftGradient = container.querySelector('.scroll-gradient.left');
  const rightGradient = container.querySelector('.scroll-gradient.right');

  if (!scrollWrapper || !leftGradient || !rightGradient) return;

  const scrollLeft = scrollWrapper.scrollLeft;
  const scrollWidth = scrollWrapper.scrollWidth;
  const clientWidth = scrollWrapper.clientWidth;
  const maxScroll = scrollWidth - clientWidth;

  // Show left gradient if scrolled right (hidden items on left)
  if (scrollLeft > 10) {
    leftGradient.classList.remove('hidden');
  } else {
    leftGradient.classList.add('hidden');
  }

  // Show right gradient if not scrolled to end (hidden items on right)
  if (scrollLeft < maxScroll - 10) {
    rightGradient.classList.remove('hidden');
  } else {
    rightGradient.classList.add('hidden');
  }
}

// Apply to tab bar
function updateTabScrollGradients() {
  const tabContainer = document.querySelector('.tab-container');
  updateScrollGradients(tabContainer);
}

// Apply to recent connections
function updateRecentConnectionsGradients() {
  const recentContainer = document.querySelector('.recent-connections-section');
  updateScrollGradients(recentContainer);
}

// Arrow key navigation
document.addEventListener('keydown', (e) => {
  // Only if no modal is open
  if (document.querySelector('.modal:not(.hidden)')) return;

  const scrollWrapper = document.querySelector('.tab-scroll-wrapper');

  if (e.key === 'ArrowLeft') {
    e.preventDefault();
    scrollWrapper.scrollBy({ left: -150, behavior: 'smooth' });
  } else if (e.key === 'ArrowRight') {
    e.preventDefault();
    scrollWrapper.scrollBy({ left: 150, behavior: 'smooth' });
  }
});

// Scroll active tab into view
function scrollTabIntoView(tabId) {
  const tab = document.querySelector(`[data-tab-id="${tabId}"]`);
  if (!tab) return;

  tab.scrollIntoView({
    behavior: 'smooth',
    block: 'nearest',
    inline: 'center'
  });
}

// Listen for scroll events to update gradients
document.querySelector('.tab-scroll-wrapper').addEventListener('scroll', updateTabScrollGradients);

// Initialize on load
window.addEventListener('load', updateTabScrollGradients);
```

**Edge Cases:**

**Few Tabs (No Overflow):**
- Gradients hidden
- No scrolling needed
- Tabs left-aligned

**Exactly Fits:**
- If tabs exactly fit available space, no gradients
- Small scroll buffer (10px) prevents flickering

**Narrow Window:**
- Tab max-width reduces to 150px minimum
- More aggressive scrolling needed
- Gradients always visible (unless only 1-2 tabs)

**Active Tab Off-Screen:**
- Auto-scroll triggered on tab switch
- Centers active tab if possible
- If at edge, scrolls to make it fully visible

**Fast Tab Switching:**
- Debounce scroll events to prevent animation stutter
- Cancel pending scroll if new tab selected

**Pop-Out Tab:**
- When tab is popped out, it disappears from tab bar
- May reduce overflow, hide gradients if tabs now fit

### 3. Multi-Window Support (Pop-Out/Pop-In)

**Description:** Allow terminal tabs to be popped out to separate windows for multi-monitor setups, then popped back in.

**User Stories:**
- As a user, I want to move a terminal to a second monitor while keeping the main app on my primary monitor
- As a user, I want to pop a window back into a tab when I'm done with multi-monitor work
- As a user, I want pop-out windows to close when I close the main app

---

**Pop-Out Window:**

**Trigger:**
- Click "Pop Out to Window" in meatball menu
- OR use Cmd/Ctrl+Shift+O keyboard shortcut

**Behavior:**
- Creates new Tauri window
- Window label: `terminal-[uuid]`
- Window title: `SSH Profile Manager - [profile-name]`
- Window size: 800x600 (default), resizable
- Window contains:
  - Minimal header with "Pop Back In" button
  - xterm.js terminal (full height)
  - No tab bar, no Profiles content
- Original tab disappears from main window
- Session remains active (PTY continues running)

**Pop-In:**

**Trigger:**
- Click "Pop Back In" button in pop-out window header

**Behavior:**
- Terminal moves back to main window as a new tab
- Tab appended to right side of tab bar
- Tab becomes active
- Pop-out window closes
- Session remains active (no reconnection)

**Window Lifecycle:**

**Main Window Closed:**
- All pop-out windows close automatically
- All sessions terminate with confirmation prompts
- Standard app quit behavior

**Pop-Out Window Closed:**
- Triggers same close confirmation as tab close
- If confirmed, session terminates, window closes
- Tab does NOT return to main window

**Multiple Pop-Outs:**
- Users can pop out multiple terminals simultaneously
- Each has independent window
- Each tracked by unique window label
- All managed independently

```rust
#[tauri::command]
async fn pop_out_terminal(
    app_handle: tauri::AppHandle,
    tab_id: String,
    profile_name: String,
) -> Result<String, String> {
    let window_label = format!("terminal-{}", uuid::Uuid::new_v4());
    let window_title = format!("SSH Profile Manager - {}", profile_name);

    let window = tauri::WindowBuilder::new(
        &app_handle,
        &window_label,
        tauri::WindowUrl::App("terminal-window.html".into())
    )
    .title(&window_title)
    .inner_size(800.0, 600.0)
    .resizable(true)
    .build()
    .map_err(|e| e.to_string())?;

    // Pass tab_id to window via IPC
    window.emit("init-terminal", &tab_id).map_err(|e| e.to_string())?;

    Ok(window_label)
}
```

### 4. Tab Performance & Memory Management

**Goal:** Ensure smooth performance with 10+ concurrent terminal tabs

**Strategies:**

**Terminal Instance Reuse:**
- Keep xterm.js instances alive when tab is inactive (hidden via CSS)
- Don't destroy/recreate terminals on tab switch
- Terminals continue receiving data when inactive
- Only destroy when tab is closed

**Memory Monitoring:**
- Each xterm.js instance: ~2-5MB memory
- Each PTY process: ~10-20MB memory
- Recommend max 10 concurrent tabs in documentation
- No hard limit enforced (user discretion)

**Scrollback Buffer:**
- Default: 1000 lines (moderate memory usage)
- User configurable in v0.8.0 (100-10000 lines)
- Large buffers may impact performance on older machines

**Tab Switching Optimization:**
- Use CSS `display: none/block` toggle (instant)
- Active tab gets focus immediately
- Terminal auto-scrolls to bottom on switch
- No flicker or delay

**Session Cleanup:**
- Close terminal tab → terminate PTY immediately
- Close pop-out window → terminate PTY with confirmation
- App quit → terminate all PTYs with confirmation
- No orphaned processes

**Lazy Loading (Future - v0.9.0+):**
- Inactive terminals pause data buffering (reduce memory)
- Re-activate when tab becomes active
- Requires PTY pause/resume support

## Technical Considerations

### Performance

**Multiple Terminals:**
- Each xterm.js instance: ~2-5MB memory
- Each PTY process: ~10-20MB memory
- Recommend max 10 concurrent tabs (document in UI)
- No hard limit enforced (user discretion)

**Tab Switching:**
- Use CSS `display: none/block` toggle (instant)
- Don't destroy terminal instances when hidden
- Terminals continue receiving data when inactive

### State Management

**Tab State:**
- Stored in JavaScript `appState` object
- Not persisted to database (tabs cleared on app restart)
- Session state tracked per tab (sessionId, status, profileId)

**Active Tab:**
- Tracked in `appState.activeTabId`
- Synced with visible content view
- Persisted to localStorage (restore on app restart)

### Accessibility

**Tab Navigation:**
- Full keyboard support (Tab key cycles through tabs)
- Arrow keys within tab bar to switch tabs
- Screen reader announcements for tab changes

**Focus Management:**
- Active tab auto-focuses terminal on switch
- Profiles tab auto-focuses search input on switch
- Modal overlays trap focus (Settings, Profile editor)

**ARIA Labels:**
- Tabs: `role="tab"`, `aria-selected`, `aria-controls`
- Tab list: `role="tablist"`
- Content areas: `role="tabpanel"`

### Security

**Session Isolation:**
- Each terminal tab has independent PTY session
- Sessions don't share state or credentials
- Existing session management already handles this

**Pop-out Windows:**
- Created via Tauri API (secure)
- No eval() or dynamic code execution
- Window labels tracked (prevent hijacking)

## Risks & Mitigations

**Risk:** App-level tabs are major UI change, users may be confused
**Mitigation:** Very similar to browser tabs (familiar pattern), add onboarding tooltip on first launch

**Risk:** Multiple terminals consume significant memory (10+ tabs)
**Mitigation:** No hard limit, but document performance impact, recommend max 10 tabs

**Risk:** Tab switching feels laggy with many terminals
**Mitigation:** Use CSS display toggle (instant), don't destroy terminals when hidden

**Risk:** Pop-out windows complicate state management
**Mitigation:** Track window labels, clean up on close, use Tauri's window lifecycle events

**Risk:** Tab overflow scrolling feels clunky
**Mitigation:** Smooth animations, gradient indicators, auto-scroll active tab
