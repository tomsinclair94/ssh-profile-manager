## 🚨 CRITICAL ISSUES (Must Fix)

### C-1: SQL REPLACE on Group Path Update Can Corrupt Data
**Source:** Code Review
**Location:** `src-tauri/src/lib.rs:2446-2451, 2664-2669`
**Risk:** Data corruption - profiles silently moved to wrong groups

**Problem:**
```rust
UPDATE profiles SET group_path = REPLACE(group_path, ?1, ?2) WHERE ...
```
Uses substring replacement. Group "Dev" renamed to "Development" would corrupt unrelated "DevOps" paths:
- `REPLACE('DevOps/Servers', 'Dev', 'Development')` → `DevelopmentOps/Servers` ❌

**Fix:**
```rust
UPDATE profiles
SET group_path = ?2 || SUBSTR(group_path, LENGTH(?1) + 1)
WHERE group_path = ?1 OR group_path LIKE ?3
```

**Files to Change:**
- `update_group` command (line 2446-2451)
- `move_group` command (line 2664-2669)

**Verification:** Add test case for groups with overlapping name prefixes

## 🔴 HIGH PRIORITY (Fix Before Release)

### H-1: Import Functions Bypass All Input Validation (SECURITY)
**Source:** Security Audit + Code Review
**Location:** `src-tauri/src/lib.rs:2796-2936, 3200-3270, 3274-3442`
**Risk:** Command injection, data corruption via crafted import files

**Problem:**
- `create_profile` validates all fields (hostname, username, port, etc.)
- `import_profiles`, `import_profile`, `import_group` deserialize and insert with ZERO validation
- Malicious import could inject `host: "example.com; rm -rf ~"` or invalid ports/names

**Fix:**
Add validation loop in all three import functions:
```rust
for profile_export in import_data.profiles {
    let profile = profile_export.profile;
    validate_profile_name(&profile.name)?;
    validate_host_or_ip(&profile.host)?;
    validate_username(&profile.username)?;
    validate_port(profile.port as i64)?;
    if let Some(ref desc) = profile.description {
        validate_description(desc)?;
    }
    if let Some(ref gp) = profile.group_path {
        validate_group(gp)?;
    }
    if !matches!(profile.auth_method.as_str(), "key" | "password" | "none") {
        return Err(format!("Invalid auth_method: {}", profile.auth_method));
    }
    // ... then proceed with insert
}
```

**Files to Change:**
- `import_profiles` (line 2880-2933)
- `import_profile` (line 3200-3270)
- `import_group_recursive` (line 3291-3442)

**Verification:** Write tests with invalid hostnames, ports, auth_methods in import data

### H-3: N+1 Query Pattern in Import Operations
**Source:** Code Review
**Location:** `src-tauri/src/lib.rs:2841-2877, 2908-2927, 3291-3302, 3382-3387`
**Risk:** Severe performance degradation on large imports (999 profiles = minutes)

**Problem:**
- `import_profiles` calls `get_all_groups()` once per unique group path
- `import_profiles` calls `get_all_tags()` once per tag per profile
- `import_group_recursive` calls `get_all_groups()` once per group
- Result: 100 profiles with 10 groups + 5 tags = 10 + 500 + 10 + 10 = **530 full-table scans**

**Fix:**
Load collections once before loops:
```rust
let mut existing_groups = db.get_all_groups()?;
let mut existing_tags = db.get_all_tags()?;

// Inside loop: check against local collections
// After insert: update local collections
```

**Files to Change:**
- `import_profiles` (lines 2841-2927)
- `import_group_recursive` (lines 3291-3387)

**Verification:** Test import of 100+ profiles, measure time before/after

### H-4: Manual Transaction Management Without RAII Guard
**Source:** Code Review
**Location:** `src-tauri/src/lib.rs:1639-1672`
**Risk:** Panic between BEGIN/COMMIT leaves connection in broken state

**Problem:**
```rust
conn.execute("BEGIN TRANSACTION", [])?;
// ... operations
conn.execute("COMMIT", [])?;
```
If panic occurs (e.g., from `lock().expect()`), transaction never rolls back.

**Fix:**
Use rusqlite's `Transaction` API (auto-rollback on drop):
```rust
let conn = self.conn.lock().expect("Database lock poisoned");
let tx = conn.unchecked_transaction()?;

tx.execute("DELETE FROM profile_tags WHERE profile_id = ?1", [profile_id])?;
for tag_id in tag_ids {
    tx.execute("INSERT INTO profile_tags ...", (profile_id, tag_id))?;
}

tx.commit()
```

**Files to Change:** `set_profile_tags_db` function (line 1639-1672)

**Verification:** Write test that simulates error mid-transaction

### H-5: Regex Compilation Inside Hot Function Path
**Source:** Code Review
**Location:** `src-tauri/src/lib.rs:3989, 3995`
**Risk:** Performance overhead + unnecessary `regex` dependency

**Problem:**
```rust
let name_regex = regex::Regex::new(r"^[a-zA-Z0-9\-_]+$").unwrap();
let color_regex = regex::Regex::new(r"^#[0-9A-Fa-f]{6}$").unwrap();
```
Compiled from scratch on every `create_tag` call. Only two uses of `regex` crate in entire codebase.

**Fix Option 1 (preferred):** Use character-by-character validation like `validate_hostname`:
```rust
fn validate_tag_name(name: &str) -> bool {
    !name.is_empty() && name.chars().all(|c| c.is_alphanumeric() || c == '-' || c == '_')
}

fn validate_hex_color(color: &str) -> bool {
    color.len() == 7 && color.starts_with('#') &&
        color[1..].chars().all(|c| c.is_ascii_hexdigit())
}
```
Removes `regex` dependency entirely.

**Fix Option 2:** Use `LazyLock` (Rust 1.80+):
```rust
use std::sync::LazyLock;
static TAG_NAME_REGEX: LazyLock<regex::Regex> = LazyLock::new(|| {
    regex::Regex::new(r"^[a-zA-Z0-9\-_]+$").unwrap()
});
```

**Files to Change:** `create_tag` command (line 3989-4000)

**Verification:** Run tag creation benchmark before/after

### H-6: Missing StrictHostKeyChecking in Embedded Terminal (SECURITY)
**Source:** Security Audit
**Location:** `src-tauri/src/lib.rs:4139-4161`
**Risk:** MITM vulnerability in embedded terminal connections

**Problem:**
- `connect_ssh` → uses `build_ssh_args()` → includes `-o StrictHostKeyChecking=ask` (line 4611)
- `create_terminal_session` → builds args manually → **missing** StrictHostKeyChecking
- Uses system default (may be `no` or `accept-new`), silently accepting changed host keys

**Fix:**
Refactor to use shared argument builder:
```rust
let ssh_args = build_ssh_args(&profile)?;
let cmd = Pair::new(
    OsString::from("ssh"),
    ssh_args.into_iter().map(OsString::from).collect()
);
```

### M-1: Conflict Dialog XSS via Unescaped Names (SECURITY)
**Location:** `dist/main.js:5498, 5545`
**Risk:** XSS injection via crafted import file

**Problem:**
```javascript
firstLine.innerHTML = `A profile named <span class="profile-name">${profileName}</span> ...`;
```

Import file with `"name": "<img src=x onerror=alert(1)>"` injects HTML. CSP blocks scripts but CSS exfiltration possible.

```javascript
firstLine.innerHTML = `A profile named <span class="profile-name">${escapeHtml(profileName)}</span> ...`;
```

### M-3: SQL LIKE Pattern Injection in Group Paths (SECURITY)
**Location:** `src-tauri/src/lib.rs:2449-2450, 2483-2486, 2513-2516, 2667-2668`
**Risk:** Unintended profile matches when group names contain underscores

**Problem:**
```rust
format!("{}/%", group.path)  // "Test_Group/%" matches "TestXGroup/%"
```
Underscore is LIKE wildcard and is allowed in group names.

**Fix:**
```rust
let escaped_path = old_path.replace('%', "\\%").replace('_', "\\_");
format!("{}/%", escaped_path)
// Add to query: ESCAPE '\\'
```

**Files:** `update_group`, `delete_group`, `move_group`

### M-4: HMAC and Encryption Use Same Derived Key (SECURITY)
**Location:** `src-tauri/src/lib.rs:1978, 1995, 2048, 2051`
**Risk:** Key separation principle violation (theoretical concern)

**Problem:**
Same PBKDF2-derived key used for AES-256-GCM encryption AND HMAC-SHA256. No practical attack known but violates defence-in-depth.

**Fix Option 1 (document):** Add comment that HMAC is intentional fail-fast check, AES-GCM already provides authentication

**Fix Option 2 (separate keys):**
```rust
let key = Aes256Gcm::generate_key(&mut OsRng);
let hmac_key = Sha256::digest(&key); // Derive separate HMAC key
```
