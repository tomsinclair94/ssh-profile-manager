# v0.8.0 — Profile & Group Moving + Custom Sort Order

## Context

Currently, profiles and groups cannot be moved without deleting and recreating them. Users who want to reorganise their SSH profiles must delete and re-add them, losing any metadata. Additionally, the only sort order available is A-Z, which may not match a user's preferred workflow order. This release adds four interconnected features:

1. **Move Profile** — modal to move a profile to a different group
2. **Move Group** — modal to move any group to a new parent (all groups, including top-level)
3. **Drag Profile Between Groups** — drag a profile card to a group header to move it instantly (with undo)
4. **Custom Sort Order** — drag profiles and groups into custom order within their parent; lock toggle + reset

## Phase 3: Drag Profile Between Groups

> Prerequisite: Phase 1 (`move_profile` command) + Phase 2 (lock state)

### Implementation approach: HTML5 Drag and Drop

Profile cards (`data-id`) get `draggable="true"` when unlocked. Group headers and the "Ungrouped" section are drop targets.

Event flow:
1. `dragstart` on profile card → store `draggingProfileId`, add `.dragging` class
2. `dragover` on group header → `e.preventDefault()`, add `.drag-over` highlight class
3. `dragleave` on group header → remove `.drag-over` class
4. `drop` on group header → call `moveProfileDragDrop(profileId, newGroupPath)`
5. `dragend` on profile card → clean up classes

```js
async function moveProfileDragDrop(profileId, newGroupPath) {
  const profile = profiles.find(p => p.id === profileId);
  const oldGroupPath = profile.group_path;
  if (oldGroupPath === newGroupPath) return; // No-op if same group

  await invoke('move_profile', { profileId, newGroupPath });
  await loadProfiles();
  showUndoToast(`Moved "${profile.name}" to ${newGroupPath || 'Ungrouped'}`, async () => {
    await invoke('move_profile', { profileId, newGroupPath: oldGroupPath });
    await loadProfiles();
  });
}
```

### Undo Toast

`showUndoToast(message, undoFn, duration = 5000)`:
- Renders a toast with an **Undo** button
- Timeout auto-dismisses after 5s
- Clicking Undo: calls `undoFn()`, dismisses toast
- Only one pending undo at a time (a new drag move cancels the previous undo)

### Visual feedback (CSS)

- `.dragging` on card being dragged: reduced opacity (`opacity: 0.5`)
- `.drag-over` on group header drop target: highlight border/background
- Cursor changes to `grab`/`grabbing` as appropriate

## Phase 4: Custom Sort Order (Drag to Reorder Within Group)

> Prerequisite: Phase 2 (lock state)

### Backend — two new commands

```rust
#[derive(Deserialize)]
struct ProfileOrder { profile_id: String, display_order: i32 }

fn reorder_profiles(db: State<Database>, orders: Vec<ProfileOrder>) -> Result<(), String>
// Batch UPDATE profile_metadata SET display_order = ? WHERE profile_id = ?

#[derive(Deserialize)]
struct GroupOrder { group_id: String, display_order: i32 }

fn reorder_groups(db: State<Database>, orders: Vec<GroupOrder>) -> Result<(), String>
// Batch UPDATE groups SET display_order = ? WHERE id = ?
```

### Backend — include `display_order` in `ProfileWithMetadata`

Add `display_order: i32` field to `ProfileWithMetadata` struct. Update `get_all_profiles_with_metadata()` query:
```sql
SELECT p.id, p.name, ..., m.icon, COALESCE(m.is_favorite, 0), COALESCE(m.display_order, 0)
FROM profiles p LEFT JOIN profile_metadata m ON p.id = m.profile_id
ORDER BY COALESCE(m.display_order, 0), p.name
```

### Backend — new items append at bottom

When drag is enabled (`drag_reorder_enabled = true`), new profiles and groups should be appended. Changes:
- `create_profile`: after inserting metadata, if `drag_reorder_enabled` setting is `true`, query max `display_order` for the profile's group_path and set `display_order = max + 1`
- `create_group`: similarly, query max `display_order` among siblings and set `display_order = max + 1`
- `drag_reorder_enabled` setting loaded by `init()` before the create commands are used

### Frontend — sort by display_order

In `renderGroupNode()`, change:
```js
childGroups.sort((a, b) => a.name.localeCompare(b.name))
```
to:
```js
childGroups.sort((a, b) =>
    a.display_order !== b.display_order
        ? a.display_order - b.display_order
        : a.name.localeCompare(b.name)
)
```

Similarly for top-level group sort in `renderProfileList()`.

For profiles within a group, sort `groupProfiles` by `display_order, name` before rendering.

### Frontend — drag-to-reorder profiles within group

When a profile card is dragged over another profile card in the **same** group (not a group header), show an insertion line indicator between cards. On drop:
1. Build new order array for all profiles in that group
2. Call `invoke('reorder_profiles', { orders: [...] })`
3. Reload profiles (re-renders in new order)

Use `dragover` + `getBoundingClientRect()` to detect whether to insert above or below target card.

### Frontend — drag-to-reorder groups

Group headers get `draggable="true"` when unlocked. Dragging a group header over a sibling group (same parent) triggers reorder. On drop:
1. Build new order for all sibling groups
2. Call `invoke('reorder_groups', { orders: [...] })`
3. Reload groups + profiles

> Dragging a group header vs. dragging a profile card are distinguished by what `dragstart` stores (`draggingProfileId` vs `draggingGroupId`).

### Reset to A-Z

- **Per-group**: Add "Reset Group Order" to group context menu — calls `reorder_profiles` with all display_orders set to 0 for that group's profiles, and `reorder_groups` for child groups
- **Global**: Add "Reset All to Alphabetical" button in Settings — sets all display_orders to 0 everywhere

Setting display_order to 0 causes the fallback: `ORDER BY display_order, name` naturally reverts to A-Z since all values are equal.

### Tests

- `test_reorder_profiles` — sets display orders, verifies persisted
- `test_reorder_groups` — sets display orders for siblings, verifies persisted
- `test_move_profile_preserves_display_order` — moving a profile doesn't corrupt its display_order

## Additional: macOS Terminal Connection Error Feedback ✅

### Problem

When "Open in new tab" is selected and macOS blocks the `osascript` call (e.g. stale Accessibility permission under System Preferences → Privacy & Security → Accessibility), the connection silently fails — no tab opens, no error is shown. Users have no way of knowing what went wrong.

Confirmed root cause: macOS TCC (Transparency, Consent, Control) can show a permission as toggled-on but not honour it. Viewing the permission entry in System Preferences refreshes the TCC database and restores normal behaviour. This affects the production `.app` bundle, not just dev builds.

### Fix

- In `launch_macos_default_terminal()` (`lib.rs`), replace `.spawn()` with `.output()` to capture the `osascript` result
- If `osascript` exits non-zero or stderr contains a permission-related message, return an `Err(...)` from the function
- Propagate the error back through `connect_ssh` to the frontend
- In the JS `connectProfile()` handler, catch the error and show a descriptive toast:
  > "Could not open new tab — macOS may have blocked Terminal automation. Go to System Preferences → Privacy & Security → Accessibility and toggle SSH Profile Manager off and on to restore access."

### Notes

- No backend tests needed (OS-level permission behaviour cannot be unit tested)
- This is a UX improvement only — no changes to the connection logic itself
- The `delay 0.1` race condition in the AppleScript (between sending `Cmd+T` and running the script in the new tab) can also be bumped to `delay 0.3` as a minor robustness improvement while in this area

## Key Design Decisions (Confirmed)

- **Move Group scope**: All groups movable (top-level can become sub-groups and vice versa)
- **Drag move UX**: Instant + 5-second undo toast (no confirmation dialog)
- **New item placement** (when drag enabled): Append to bottom (max display_order + 1)
- **Padlock**: Button next to "Profiles" count badge + mirrored Settings toggle (both synced)
- **Sort**: Always `ORDER BY display_order, name` — reset means setting all to 0 (reverts to A-Z)
- **No schema migration needed**: `display_order` columns already exist with default 0
