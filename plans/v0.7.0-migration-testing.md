## Migration Scope

### Bundle Identifier Change

**ℹ️ macOS app identity update only — no data migration required.**

**Old Tauri identifier (tauri.conf.json):** `com.tomsinclair.sshprofilemanager` (v0.6.5 and earlier)
**New Tauri identifier (tauri.conf.json):** `app.sshprofilemanager` (v0.7.0+)

**What Stays the Same:**
- ✅ **Database file** - Unchanged at `~/Library/Application Support/ssh-profile-manager/profiles.db`
- ✅ **Keychain passwords** - Unchanged, service name stays `"ssh-profile-manager"`
- ✅ **User settings** - Preserved in database (terminal preference, etc.)

**What Resets:**
- ⚠️ **localStorage** - Resets because WebKit storage is keyed to the bundle identifier
  - WebKit old location: `~/Library/WebKit/com.tomsinclair.sshprofilemanager/`
  - WebKit new location: `~/Library/WebKit/app.sshprofilemanager/`
  - localStorage cannot be migrated between bundle IDs (WebKit-internal, no supported API)
  - **This is intentional and handled:** JS migration system detects fresh localStorage and shows upgrade toast + changelog splash

**User Impact:** On first v0.7.0 launch, all profiles and settings are preserved. localStorage resets to v0.7.0 defaults (acceptable — old values used group names instead of IDs anyway and would have needed clearing). Users see the upgrade toast and changelog splash.

### 2B. ⚠️ Dev vs Production localStorage — Important Distinction

**Dev mode (`bun run dev`) and production builds use completely separate localStorage stores on macOS.**

This is a macOS/Tauri architectural behaviour: WebKit storage is keyed to the process identity.
- **Dev mode** runs the raw binary (no bundle) → macOS falls back to the Cargo package name:
  `~/Library/WebKit/ssh-profile-manager/`
- **Production build** runs as a proper `.app` with a bundle identifier in `Info.plist`:
  `~/Library/WebKit/app.sshprofilemanager/`

| Store | Dev (`bun run dev`) | Production build |
|-------|---------------------|------------------|
| Database | `~/Library/Application Support/ssh-profile-manager/` | Same ✅ |
| Keychain | `ssh-profile-manager` service | Same ✅ |
| localStorage | `~/Library/WebKit/ssh-profile-manager/` | `~/Library/WebKit/app.sshprofilemanager/` ⚠️ **Different** |

**Rules for migration testing:**
1. **Always use a production build** (`bun run build`) for migration testing — never `bun run dev`
2. **Wipe ALL WebKit variants** before each clean test (the wildcard covers both paths):
   ```bash
   rm -rf ~/Library/WebKit/*ssh*profile*
   ```
3. **DevTools testing is fine for inspection** (dev build), but switch to production to validate the actual migration flow that real users will experience

Mixing dev and production builds mid-test will produce confusing results (e.g. toast/splash appearing or not appearing unexpectedly) because the two localStorage stores are completely independent.

#### Issue 2: Sub-Group Profiles Disappear After Group Rename ✅ FIXED (2026-02-19)
- **Status:** ✅ Fixed
- **Severity:** Medium (data is not lost, only invisible in UI)
- **Steps to reproduce:** Create a group with at least one sub-group containing profiles. Rename the parent group.
- **Root Cause:** `update_group` and `move_group` commands used a Rust for-loop with `String::replace()` to update descendant group paths. `replace()` substitutes ALL occurrences of the pattern, so renaming "Dev" to "Development" when a sub-group is named "Dev/DevOps" would corrupt its path to "Development/DevelopmentOps" — creating a mismatch with the profile cascade SQL (which correctly used SUBSTR).
- **Fix:** Replaced the for-loop in both `update_group` and `move_group` with a single SQL UPDATE using `SUBSTR` (same approach as the profile cascade). This ensures group paths and profile paths always use the same algorithm, eliminating the mismatch. Both operations now run under a single lock acquisition.
- **Test Added:** `test_rename_group_cascade_updates_sub_group_profiles` in `tests/groups.rs` — verifies the overlapping-name edge case ("Dev/DevOps" → "Development/DevOps", not "Development/DevelopmentOps").

#### ~~Issue 1: Changelog Splash Screen Not Appearing~~ (RESOLVED)
- **Status:** ✅ Resolved
- **Root Cause:** Stale localStorage data from previous test runs containing `lastSplashVersion` and `migrationToastShown` flags
- **Solution:** Complete WebView data wipe required for clean testing. Migration system works correctly when localStorage is clean.
- **Production Impact:** None — real users upgrading from v0.6.5 won't have these localStorage keys, so toast and splash show correctly.
