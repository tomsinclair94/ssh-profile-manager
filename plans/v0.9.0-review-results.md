### CRITICAL

#### C-1: `CreateCentralPasswordInput` derives `Debug`, leaking password to logs
**File:** `src-tauri/src/lib.rs:4551`

`CreateCentralPasswordInput` derives `Debug` without a custom implementation, meaning the `password` field could be printed in full to logs. This is inconsistent with `CreateProfileInput` (line 2466) and `UpdateProfileInput` (line 2588), which both have custom `Debug` impls redacting the password field to `[REDACTED]`.

**Fix:** Add a custom `Debug` implementation matching the pattern used for `CreateProfileInput`.

---

### HIGH

#### H-1: No backend validation on CP description
**File:** `src-tauri/src/lib.rs:4653-4703`, `4706-4737`

Both `create_central_password` and `update_central_password` accept `Option<String>` description without calling `validate_description()`. Profile commands consistently validate descriptions. A crafted import or API call could store a description with `<script>` tags in the database.

**Fix:**
```rust
if let Some(ref desc) = input.description {
    validate_description(desc)?;
}
```

#### H-2: `resolve_or_create_central_password_for_import` bypasses name validation
**File:** `src-tauri/src/lib.rs:3642-3662`

When importing a profile with a `central_password_ref`, the name from untrusted import JSON is inserted into the database without any length or character validation, bypassing the rules enforced by `create_central_password`.

**Fix:**
```rust
fn resolve_or_create_central_password_for_import(db: &Database, name: &str) -> Result<String, String> {
    let name = name.trim();
    if name.is_empty() || name.len() > 64 {
        return Err(format!("Invalid central password name in import: '{}'", name));
    }
    // ... rest of function
}
```

#### H-3: Frontend/backend CP name validation mismatch
**Files:** `dist/main.js:12925,12954,13061` · `src-tauri/src/lib.rs:4666,4718` · `dist/index.html:876-881`

- Frontend allows: letters, numbers, spaces, `-`, `_`, `(`, `)`, `.`, `[`, `]`, `#`
- Backend allows: letters, numbers, spaces, `-`, `_`, `(`, `)`
- HTML tooltip also incorrectly lists `.`, `[`, `]`, `#` as allowed

A user can type `Server.Prod[1]#Main`, pass frontend validation, and receive a confusing backend rejection.

**Fix:** Align the JS regex to match the backend — remove `.`, `[`, `]`, `#`. Update the HTML tooltip. Update all three JS locations: `updateCpNameCounter`, `validateCpCreateForm`, `validateAndGetCpFormValues`.

#### H-4: Password not zeroized in memory after use in `connect_ssh`
**File:** `src-tauri/src/lib.rs:5955-5965`

The `password` string retrieved from keychain is not zeroized after being written to the temp file, unlike the encryption module which consistently uses `key.zeroize()`.

**Fix:**
```rust
let mut password = get_password(&keychain_key).map_err(|_| { ... })?;
let setup = create_askpass_setup(&password)?;
password.zeroize();
Some(setup)
```

### HIGH

#### H-1: TOCTOU Race Condition in Temp File Creation
**File:** `src-tauri/src/lib.rs:5384-5398`

The password file is created with `fs::write()` (default umask, often 0644) and permissions are restricted to 0600 in a separate call. Between write and chmod, the file is world-readable. On a multi-user system another process could read it during this window. UUID-based filename provides obscurity but is not a security control.

**Fix:** Create the file atomically with restricted permissions:
```rust
#[cfg(unix)]
{
    use std::os::unix::fs::OpenOptionsExt;
    use std::io::Write;
    let mut file = std::fs::OpenOptions::new()
        .write(true)
        .create_new(true)  // Prevents symlink attacks
        .mode(0o600)
        .open(&pwd_file_path)
        .map_err(|e| format!("Failed to create temporary password file: {}", e))?;
    file.write_all(password.as_bytes())
        .map_err(|e| format!("Failed to write password file: {}", e))?;
}
```
Apply the same pattern to the askpass script creation (line 5418) using `mode(0o700)`.

### Positive Security Observations

1. **SQL injection prevention** — all new CP queries use parameterised statements, no string concatenation
2. **XSS prevention** — `escapeHtml()` applied to all user-supplied data in `renderCentralPasswordsList()`; revealed password uses `textContent` not `innerHTML`
3. **Password redaction in Debug** — `CreateProfileInput` / `UpdateProfileInput` redact passwords (gap on `CreateCentralPasswordInput` noted as C-1 in code review)
4. **CP ID verification on profile save** — `create_profile` and `update_profile` verify the referenced CP exists before saving
5. **Secure file deletion** — `delete_file_with_overwrite` overwrites with random data before deletion
6. **CSP** — well-configured with `object-src 'none'`, `frame-ancestors 'none'`, restrictive `script-src 'self'`
7. **Shell escaping** — askpass script path is shell-escaped via `shell_escape()` preventing command injection
8. **Auth method validation** — `validate_profile_fields` validates `central_password` as an allowed value
9. **Cascade cleanup on CP deletion** — correctly reverts linked profiles to `auth_method='none'` before removing keychain entry
10. **No password export for CP profiles** — exports only `central_password_ref` (name), no credential value
