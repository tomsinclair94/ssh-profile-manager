## Overview

Phase 6 implements robust encryption for export/import functionality using industry-standard cryptography. All exports containing profiles with password authentication will be mandatorily encrypted to protect sensitive credentials.

**Key Features:**
- AES-256-GCM authenticated encryption
- PBKDF2-HMAC-SHA256 key derivation (600k iterations - OWASP 2023)
- Additional HMAC-SHA256 integrity verification
- Password strength meter with visual feedback (non-enforcing)
- Mandatory encryption when password-based profiles are included
- Progress indicators for encryption/decryption operations

## Architecture Overview

### Encryption Flow
```
User Password (12+ chars)
    ↓
PBKDF2-HMAC-SHA256 (600k iterations, random 16-byte salt)
    ↓
256-bit Encryption Key
    ↓
Export Data → JSON serialize → AES-256-GCM encrypt (random 12-byte IV)
    ↓
Ciphertext + Auth Tag
    ↓
HMAC-SHA256 over (salt + IV + ciphertext)
    ↓
Base64 encode all components
    ↓
EncryptedExport struct
```

### Decryption Flow
```
EncryptedExport
    ↓
Parse and decode Base64 components
    ↓
Verify HMAC-SHA256 (fail fast if tampered)
    ↓
PBKDF2-HMAC-SHA256 (user password + stored salt)
    ↓
AES-256-GCM decrypt (verify auth tag)
    ↓
JSON deserialize
    ↓
Import data structures
```

### Data Structure

```rust
struct EncryptedExport {
    version: String,          // Export format version (e.g., "2.0")
    encrypted: bool,          // Always true for encrypted exports
    cipher: String,           // "AES-256-GCM"
    kdf: String,              // "PBKDF2-HMAC-SHA256"
    kdf_iterations: u32,      // 600000
    salt: String,             // Base64-encoded 16-byte salt
    iv: String,               // Base64-encoded 12-byte IV (nonce)
    data: String,             // Base64-encoded ciphertext
    hmac: String,             // Base64-encoded HMAC-SHA256
}
```

## Security Considerations

### Cryptographic Choices

**Why AES-256-GCM?**
- Industry standard for authenticated encryption
- Single primitive for confidentiality + integrity
- Hardware acceleration on modern CPUs (fast)
- Recommended by NIST, OWASP, and cryptographic experts

**Why PBKDF2 with 600k iterations?**
- OWASP 2023 recommendation for password-based encryption
- Sufficient resistance to brute-force attacks
- Widely supported and well-tested
- ~1-2 seconds on modern hardware (acceptable UX with spinner)

**Why additional HMAC-SHA256?**
- Defense-in-depth: AES-GCM auth tag + separate HMAC
- Fail-fast verification before decryption attempt
- Prevents certain cryptographic attacks on GCM
- Negligible performance cost

### Threat Model

**Protected Against:**
- ✅ Brute-force password attacks (600k iterations + strong password recommendation)
- ✅ Data tampering (HMAC verification)
- ✅ Chosen-ciphertext attacks (authenticated encryption)
- ✅ Timing attacks (constant-time HMAC comparison)
- ✅ Password leakage (zeroization after use)

**NOT Protected Against:**
- ❌ Weak user passwords (users can ignore strength meter)
- ❌ Keyloggers/screen capture (out of scope)
- ❌ Compromised devices (OS-level threat)
- ❌ Social engineering (user education required)

### Best Practices Implemented

1. **Random Salt/IV** - Generated per export (prevents rainbow tables, replay attacks)
2. **Zeroization** - Passwords/keys cleared from memory immediately after use
3. **Fail-Fast** - HMAC verified before attempting decryption (saves CPU, prevents attacks)
4. **Constant-Time Comparison** - HMAC verification uses constant-time algorithm
5. **Version Tracking** - Export format includes crypto parameters for future-proofing
6. **Strong Defaults** - 600k iterations, 256-bit keys, 12-byte IVs (OWASP/NIST compliant)

## Password Strength Meter Implementation

### Strength Calculation Logic

```javascript
function calculatePasswordStrength(password) {
    let score = 0;

    // Length (0-2 points)
    if (password.length >= 12) score += 1;
    if (password.length >= 16) score += 1;

    // Character variety (0-2 points)
    const hasLower = /[a-z]/.test(password);
    const hasUpper = /[A-Z]/.test(password);
    const hasNumber = /[0-9]/.test(password);
    const hasSpecial = /[^A-Za-z0-9]/.test(password);

    const variety = [hasLower, hasUpper, hasNumber, hasSpecial].filter(Boolean).length;
    if (variety >= 3) score += 1;
    if (variety === 4) score += 1;

    // Map score to label (0=weak, 1=fair, 2=good, 3-4=strong)
    const labels = ['weak', 'fair', 'good', 'strong', 'strong'];
    const colors = ['#dc2626', '#f97316', '#eab308', '#22c55e', '#22c55e'];

    return {
        score,
        label: labels[score],
        color: colors[score],
        percentage: (score / 4) * 100
    };
}
```

### Visual Feedback

- **Weak (0-1 points):** Red bar (0-25%), text: "Weak password"
- **Fair (2 points):** Orange bar (50%), text: "Fair password"
- **Good (3 points):** Yellow bar (75%), text: "Good password"
- **Strong (4 points):** Green bar (100%), text: "Strong password"

### User Guidance

Below password input, show recommendations:
- ✅ At least 12 characters
- ✅ Mix of uppercase and lowercase letters
- ✅ Include numbers
- ✅ Include special characters (!@#$%^&*)

**Note:** These are recommendations only - not enforced. Users can proceed with weak passwords (their choice, but we guide them).

### Export Errors

| Error | User-Friendly Message | Technical Cause |
|-------|----------------------|-----------------|
| Missing encryption password | "Encryption required: This export contains password-authenticated profiles. Please provide an encryption password." | Password profile detected, no encryption_password provided |

| Error | User-Friendly Message | Technical Cause |
|-------|----------------------|-----------------|
| No password provided | "This import is encrypted. Please provide the decryption password." | Encrypted file, no password given |

| Corrupted data | "Import file is corrupted or invalid. Cannot import." | JSON parse error after decryption |

## Known Limitations (Acceptable for v0.7.0)

- **No password recovery:** If user forgets encryption password, data is unrecoverable (by design)
- **No password complexity enforcement:** Users can choose weak passwords (strength meter guides but doesn't block)
- **Single encryption method:** No option to choose different ciphers (AES-256-GCM only)
- **No key rotation:** Encrypted exports cannot be re-encrypted with new password without decrypting first

**Future Considerations (v0.8.0+):**
- Hardware security module (HSM) integration for enterprise users
- Two-factor authentication for encryption (e.g., hardware key + password)
- Encrypted local database (not just exports)
- Cloud backup with end-to-end encryption
