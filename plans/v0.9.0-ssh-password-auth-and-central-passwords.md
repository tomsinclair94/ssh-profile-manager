# v0.9.0 Feature Plan: SSH Password Auth & Central Passwords

**Status:** Planned — assigned to v0.9.0
**Branch:** `v0.9.0-dev` (not yet created)

## Platform Support

- **macOS:** Latest (Apple Silicon)
- **Windows:** Windows 11 only — Windows 10 is no longer supported as of v0.9.0
- `SSH_ASKPASS_REQUIRE=force` requires OpenSSH 8.4+ — ships with both platforms by default

---

## Overview

Two related features that together make password-based SSH authentication actually useful:

1. **SSH_ASKPASS fix** — passwords are stored in keychain but never used during connection. SSH must receive them via the `SSH_ASKPASS` mechanism (a helper program that outputs the password when SSH needs it). This fixes the core bug.

2. **Central Passwords** — shared credential objects referenced by multiple profiles. Change one password, all linked profiles immediately use the new value. Designed for AD environments where many profiles share one rotating password.

These are implemented in order — Phase 1 is a prerequisite for Phase 2 (`connect_ssh` must pass passwords before central passwords are useful).

## Phase 1: SSH_ASKPASS Infrastructure

**Goal:** Passwords stored in keychain are actually used when connecting.

### 1a. New Rust helpers in lib.rs

**New struct** (add near other structs, before `connect_ssh`):
```rust
struct AskpassSetup {
    askpass_script_path: std::path::PathBuf,
    pwd_file_path: std::path::PathBuf,
}
```

**New function `create_askpass_setup(password: &str) -> Result<AskpassSetup, String>`:**
- Write password bytes to temp file with UUID name (`spm-pwd-{uuid}`) — `0600` permissions on Unix, `create_file_windows_secure()` on Windows
- Write a platform askpass script with UUID name:
  - macOS/unix: `spm-askpass-{uuid}.sh` — `#!/bin/sh\ncat '/path/to/pwd_file'\n` — set `0700` permissions
  - Windows: `spm-askpass-{uuid}.bat` — `@echo off\r\ntype "C:\path\to\pwd_file"\r\n`
- Return `AskpassSetup { askpass_script_path, pwd_file_path }`
- Use existing `Uuid::new_v4()` (already imported), `std::env::temp_dir()`, and `delete_file_with_overwrite()` patterns

**New function `schedule_askpass_cleanup(setup: AskpassSetup)`:**
- Spawns a thread (like existing cleanup pattern in `launch_macos_custom_terminal`) with 10s delay
- Calls `delete_file_with_overwrite()` on both files

### 1b. Modify `connect_ssh` (lib.rs:5242)

After profile validation, before calling launch functions:

```rust
// Retrieve password and set up askpass if password auth
let askpass_setup = if profile.auth_method == "password" {
    let password = get_password(&profile_id).map_err(|_| {
        "No password stored for this profile. Edit the profile to set a password, \
         or switch to a different authentication method.".to_string()
    })?;
    if password.is_empty() {
        return Err("No password stored for this profile. Edit the profile to set a password, \
                    or switch to a different authentication method.".to_string());
    }
    Some(create_askpass_setup(&password)?)
} else {
    None
};
```

Pass `askpass_setup.as_ref()` to each launch function. After all launch functions, call `schedule_askpass_cleanup()` if setup is Some.

### 1c. Modify all 7 launch functions

Each gets `askpass_setup: Option<&AskpassSetup>` as a final parameter. Where branching is required, the non-password path is entirely unchanged.

**`launch_macos_default_terminal`:**
- Non-password: unchanged
- With password: prefix the SSH command in the AppleScript `do script` string with inline env vars (POSIX sh syntax, scoped to the ssh call only):
  ```
  SSH_ASKPASS='/path/to/askpass.sh' SSH_ASKPASS_REQUIRE=force ssh [args]
  ```
  Use `shell_escape()` on the askpass path.

**`launch_macos_custom_terminal`:**
- Non-password: unchanged
- With password: add two `export` lines to the existing temp bash script immediately before the `ssh` line:
  ```bash
  export SSH_ASKPASS='/path/to/askpass.sh'
  export SSH_ASKPASS_REQUIRE=force
  ```
  No structural change — the script already exists.

**`launch_windows_cmd`:**
- Non-password: unchanged (direct `cmd /c start cmd /c ssh [args] & exit`)
- With password: inline `set` chain — build a single compound command string and pass as one arg to `/c`. No temp file created:
  ```
  set "SSH_ASKPASS=C:\...\spm-askpass-uuid.bat"& set "SSH_ASKPASS_REQUIRE=force"& ssh [args]& exit
  ```
  Use `set "VAR=VALUE"` syntax (quotes around the full assignment) to safely handle paths with spaces (e.g. username with spaces in `%TEMP%` path).

**`launch_windows_powershell`:**
- Non-password: unchanged
- With password: prepend env var assignments to the PS command string before base64 encoding — no structural change, no temp file:
  ```powershell
  $env:SSH_ASKPASS = 'C:\path\askpass.bat'; $env:SSH_ASKPASS_REQUIRE = 'force';
  ```

**`launch_windows_terminal` (wt):**
- Non-password: unchanged (`wt --title [name] ssh [args]`)
- With password: cannot inject env vars via wt command-line args — a temp `.bat` script is unavoidable here. Branch to a temp `.bat` with `set` lines + `ssh`, then launch `wt --title [name] cmd /c [script.bat]`. Schedule cleanup.
- **Known limitation:** In environments where AppLocker/WDAC blocks `.bat` execution from `%TEMP%`, password auth via Windows Terminal will fail. Users in such environments should switch to Command Prompt or PowerShell in settings.

**`launch_windows_custom_terminal`:**
- Non-password: unchanged (already uses a temp `.bat` script — unavoidable for this mode)
- With password: add `set "SSH_ASKPASS=..."` and `set "SSH_ASKPASS_REQUIRE=force"` lines to the existing batch script immediately before the `ssh` line. No structural change.

**`launch_windows_default_terminal`:**
- wt path — Non-password: unchanged. With password: same branch as `launch_windows_terminal` (temp `.bat` + `wt cmd /c [script.bat]`). Same known limitation applies.
- cmd fallback — Non-password: unchanged. With password: same inline `set` chain as `launch_windows_cmd`. No temp file.

## Phase 3: Export/Import for Central Passwords

### Profile export

Add `central_password_ref: Option<String>` to `ProfileExportDetailed`. When profile has `central_password_id`:
- Set `central_password_ref = Some(central_password.name)`
- Do NOT include password value (even if `include_password=true`) — the central password is machine-local
- Encryption is only required if an individual profile password is being exported

### Profile import

If imported JSON contains `central_password_ref`:
1. Look up central password by name in local DB
2. If found: set `central_password_id = found.id`, `auth_method = "password"`
3. If not found: create new `CentralPassword` DB row with that name, empty description, no keychain entry yet
4. Set profile's `central_password_id` to the new/found ID

**Handling "empty shell" central passwords:** When created during import with no password set, the keychain entry simply won't exist. `connect_ssh` will return the "no password stored" error with a message guiding the user to set it via the Central Passwords manager. This is intentional — the user must set their own password.
