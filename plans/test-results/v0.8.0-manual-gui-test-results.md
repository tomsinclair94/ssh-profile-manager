# Manual GUI Test Plan — v0.8.0

**Purpose:** Focused manual testing of all features and changes introduced in v0.8.0. Existing features not touched by this release are not retested here.
**Scope:** Move Profile, Move Group, Padlock button, Drag Profile Between Groups, Custom Sort Order, Expand Card Actions setting, Text Selection Containment, macOS Terminal Error Feedback, Settings Modal polish.

---

## Pre-Testing Setup

### Test Data Creation
- [ ] Create the following group structure:
  - `Work` (top-level)
    - `Work/Staging` (child)
    - `Work/Production` (child)
      - `Work/Production/EU` (grandchild — needed for 3-level depth tests)
  - `Personal` (top-level)
- [ ] Create 10+ profiles spread across groups:
  - 2–3 in `Work/Staging`
  - 2–3 in `Work/Production`
  - 2 in `Personal`
  - 2 ungrouped
- [ ] Mark 1–2 profiles as favourites (needed to verify Favourites excluded as drag target)
- [ ] Keep at least 2 profiles ungrouped throughout testing (needed for move-to-ungrouped tests)

## macOS Testing

### 1. Move Profile

#### Basic Move
- [ ] Right-click a profile card (or click the Actions menu) — verify "Move Profile" menu item present
- [ ] Click "Move Profile" — verify Move modal opens with title "Move Profile"
- [ ] Verify the modal shows the profile's current group pre-selected in the dropdown
- [ ] Verify the dropdown lists all groups (including nested paths like `Work/Production`)
- [ ] Verify "Ungrouped" is an option in the dropdown
- [ ] Type in the search box — verify dropdown filters groups
- [ ] Select a different group and click "Move"
- [ ] Verify profile disappears from old group and appears in the new group
- [ ] Verify a success toast appears
- [ ] Move the profile back (undo manually by moving again)

#### Move to Ungrouped
- [ ] Open "Move Profile" for a profile that is in a group
- [ ] Select "Ungrouped" from the dropdown
- [ ] Click "Move"
- [ ] Verify profile now appears in the Ungrouped section
- [ ] Move it back to a group to restore test data

#### Modal Behaviour
- [ ] Open Move Profile modal → press `Escape` → verify modal closes with no change
- [ ] Open Move Profile modal → press `Cmd+S` → verify it saves (same as clicking "Move")
- [ ] Open Move Profile modal → press `Tab` → verify focus cycles through: search input → dropdown options → Move button → Cancel button → back to start
- [ ] Click "Cancel" → verify modal closes with no change

### 2. Move Group

#### Basic Move
- [ ] Open the context menu for `Work/Staging` — verify "Move Group" menu item present
- [ ] Click "Move Group" — verify Move modal opens with title "Move Group"
- [ ] Verify the current parent (`Work`) is pre-selected
- [ ] Verify dropdown lists valid destinations (all groups except self and its own descendants)
- [ ] Verify "Top level (no parent)" is an option
- [ ] Move `Work/Staging` to `Personal` — verify it now appears as `Personal/Staging`
- [ ] Verify all profiles within `Staging` still exist and are now at path `Personal/Staging`
- [ ] Move it back to `Work` to restore

#### Move to Top Level
- [ ] Open "Move Group" for `Work/Production/EU` (grandchild)
- [ ] Select "Top level (no parent)"
- [ ] Click "Move"
- [ ] Verify `EU` appears as a top-level group
- [ ] Verify profiles previously at `Work/Production/EU/...` are now under `EU/...`
- [ ] Move `EU` back under `Work/Production` to restore

#### Depth Limit Enforcement
- [ ] With `Work/Production/EU` as a grandchild, attempt to move another group under `EU` (4th level should be prevented)
- [ ] Verify `EU` does NOT appear as a valid destination in the "Move Group" dropdown for any group (max 3 levels enforced)

#### Modal Behaviour
- [ ] Open Move Group modal → press `Escape` → verify closes with no change
- [ ] Open Move Group modal → press `Cmd+S` → verify saves (moves the group)
- [ ] Click "Cancel" → verify no change

### 3. Padlock Button

#### Initial State
- [ ] Launch app (fresh session) — verify padlock button in toolbar (next to profile count badge) shows the **locked** state (amber/gold colour, lock icon)
- [ ] Hover over padlock — verify tooltip says something like "Drag reordering is locked — click to enable"

#### Toggle
- [ ] Click the padlock — verify it switches to **unlocked** state (neutral colour, open lock icon)
- [ ] Verify tooltip changes to reflect unlocked state
- [ ] Click the padlock again — verify it returns to **locked** state

#### Session Persistence
- [ ] Unlock the padlock
- [ ] Open and close a modal (e.g., Settings) — verify padlock remains unlocked
- [ ] Scroll up and down the profile list — verify padlock state unchanged
- [ ] Quit the app fully and relaunch — verify padlock is back to **locked** state (session reset)

#### No Settings Entry
- [ ] Open Settings — verify there is **no** "Enable drag reordering" or similar checkbox anywhere in Settings
- [ ] Verify padlock state is not included in Settings Backup/Restore (no entry in exported JSON)

### 4. Drag Profile Between Groups

> Prerequisite: Unlock the padlock before running these tests.

#### Drag to Group Header
- [ ] Unlock the padlock
- [ ] Verify profile cards show a grab cursor on hover
- [ ] Drag a profile from `Work/Staging` and drop it onto the `Work/Production` group header
- [ ] Verify the profile disappears from `Work/Staging` and appears in `Work/Production`
- [ ] Verify a **5-second undo toast** appears (e.g., "Moved 'ProfileName' to Work/Production")

#### Undo Toast
- [ ] Drag a profile to a different group
- [ ] Immediately click the **Undo** button in the toast
- [ ] Verify the profile is moved back to its original group
- [ ] Drag a different profile
- [ ] Wait 5 seconds — verify the toast auto-dismisses without undoing

#### Drag to Ungrouped
- [ ] Drag a profile from a group and drop it onto the **Ungrouped** section header
- [ ] Verify profile appears in Ungrouped
- [ ] Undo or move it back manually

#### Favourites Excluded as Drop Target
- [ ] Drag a profile and hover over the **Favourites** virtual group header
- [ ] Verify no drop highlight appears on the Favourites header
- [ ] Verify dropping onto Favourites does **not** move the profile (it stays where it was)

#### Visual Feedback
- [ ] Start dragging a profile card — verify card shows reduced opacity (`.dragging` state)
- [ ] Hover dragged card over a group header — verify group header shows a highlight (`.drag-over` state)
- [ ] Move away from the group header — verify highlight disappears

#### Drag Locked State
- [ ] Lock the padlock
- [ ] Attempt to drag a profile card — verify dragging is not possible (no `.dragging` behaviour, no grab cursor)

### 5. Custom Sort Order (Drag to Reorder)

> Prerequisite: Unlock the padlock before running these tests.

#### Reorder Profiles Within a Group
- [ ] Unlock the padlock
- [ ] Drag a profile card within `Work/Staging` and drop it above another profile in the same group
- [ ] Verify a **blue insertion line** appears between cards as you drag (position indicator)
- [ ] Release — verify profile appears in the new position
- [ ] Quit and relaunch the app — verify the custom order persists (profiles still in user-defined order)

#### Reorder Profiles Across Groups (Cross-Group Drag + Position)
- [ ] Drag a profile from `Work/Staging` and hover over a specific position **within** `Work/Production` (between two existing cards)
- [ ] Verify the insertion line appears at the target position within `Work/Production`
- [ ] Drop — verify the profile is moved to `Work/Production` **at the exact drop position** (not appended to the bottom)
- [ ] Verify a 5s undo toast appears
- [ ] Undo — verify the profile returns to its original group and position

#### Reorder Groups
- [ ] Drag the `Work/Staging` group header and drop it after `Work/Production` (reorder siblings)
- [ ] Verify `Work/Production` now appears before `Work/Staging` in the list
- [ ] Verify that dragging a group header to a **different parent** is not possible (only same-parent siblings)
- [ ] Quit and relaunch — verify group order persists

#### Reset Group Order ("Reset to A-Z")
- [ ] After reordering profiles within `Work/Staging`, right-click the `Work/Staging` group header
- [ ] Verify "Reset to A-Z" option appears in the context menu
- [ ] Click "Reset to A-Z"
- [ ] Verify profiles within `Work/Staging` return to alphabetical order
- [ ] Verify profiles in other groups are unaffected

#### Reset All Sorting (Settings)
- [ ] Reorder some profiles and groups
- [ ] Open Settings
- [ ] Verify "Reset Sorting Order" button is present
- [ ] Click it — verify a confirmation dialog appears
- [ ] Cancel — verify no change
- [ ] Click "Reset Sorting Order" again and confirm
- [ ] Verify all profiles and groups in every group revert to alphabetical order

#### New Items Append at Bottom
- [ ] Ensure padlock is unlocked
- [ ] Create a new profile in `Work/Staging` — verify it appears **at the bottom** of that group (not alphabetically inserted)
- [ ] Create a new group — verify it appears at the bottom of the group list

### 6. Expand Card Actions Setting

#### Enable Setting
- [ ] Open Settings → Appearance
- [ ] Verify "Expand card actions" checkbox is present and **unchecked** by default
- [ ] Check the checkbox and save
- [ ] Verify profile cards now show 6 individual buttons: Connect, Edit, Move, Duplicate, Export, Delete
- [ ] Verify button layout is a 3×2 grid (Connect/Edit/Move on row 1, Duplicate/Export/Delete on row 2)
- [ ] Verify button colours: Connect = green, Edit = blue, Move/Duplicate/Export = grey, Delete = red

#### Button Functionality (Expanded Layout)
- [ ] Click **Connect** button on a card — verify it opens the connect dialog/terminal
- [ ] Click **Edit** button on a card — verify it opens the Edit Profile modal
- [ ] Click **Move** button on a card — verify it opens the Move Profile modal
- [ ] Click **Duplicate** button on a card — verify it duplicates the profile
- [ ] Click **Export** button on a card — verify it opens the export flow
- [ ] Click **Delete** button on a card — verify it opens the delete confirmation dialog

#### Compact View Fallback
- [ ] With the setting enabled, resize the app window to below ~800px width
- [ ] Verify profile cards **revert to standard Connect + Actions layout** (expanded buttons hidden)
- [ ] Resize back to normal width — verify expanded buttons reappear

#### Persistence & Backup
- [ ] Save the setting enabled, quit and relaunch app — verify setting persists (expanded buttons still shown)
- [ ] Open Settings → Backup & Restore → Export Settings — open the JSON file
- [ ] Verify `expanded_card_actions_enabled: true` is present in the exported JSON
- [ ] Disable the setting, then restore the settings file — verify expanded buttons reappear (setting restored)

#### Disable Setting
- [ ] Uncheck the checkbox and save
- [ ] Verify profile cards revert to standard Connect + Actions layout

### 7. Text Selection Containment

- [ ] Click and drag to select text within a **profile card title** (e.g., profile name) — verify text highlights correctly
- [ ] With text selected in a profile card title, drag the selection to try to extend it to an adjacent profile card — verify selection does **not** bleed across to the other card
- [ ] Select text within a **group name** — verify it highlights correctly
- [ ] Try to drag that selection outside the group name element — verify selection is cleared before it escapes
- [ ] Select text in a **hostname or username field** on a profile card — verify it works correctly and stays contained
- [ ] Press `Cmd+A` while focus is on the profile list — verify it does **not** select all text on the page
- [ ] Click inside an **input field** (e.g., search box) and press `Cmd+A` — verify it selects all text in the input (works normally inside inputs)
- [ ] Click and drag to select a group name, then single-click the group header — verify the group does **not** collapse/expand while text is selected

#### Tab Navigation

- [ ] Press `Tab` repeatedly — verify focus cycles through all focusable toolbar buttons including the **padlock button** (should be included in the Tab cycle)
- [ ] Verify the drag-lock-btn is reachable via Tab from the toolbar area

#### UK Spelling Check
