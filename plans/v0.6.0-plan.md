# SSH Profile Manager v0.6.0 Implementation Plan

**Date:** 2024-12-29
**Version:** 0.6.0
**Branch:** v0.6.0-dev

## Overview

This plan covers implementation of four major features for v0.6.0:
1. **Keyboard Shortcuts** - Quick navigation and actions via keyboard
2. **Recent Connections** - Track and display recent connection history
3. **Embedded Terminal with Multi-Tab Support** - xterm.js-based in-app terminal with multiple concurrent sessions
4. **Terminal Customization** - Font, colors, cursor, scrollback settings

**Deferred to v0.7.0:** Full connection history/logs with filters and detailed tracking.

## Database Schema Changes

### Migration System

Create `schema_version` table to track migrations:

```sql
CREATE TABLE schema_version (
    version INTEGER PRIMARY KEY,
    applied_at TEXT NOT NULL
);
```

Implement `apply_migrations()` function called in `Database::new()`:
- Check current version
- Apply missing migrations in order
- Update schema_version table
- Support rollback on failure

### New Tables

```sql
-- Track recent connections (simplified vs full history - deferred to v0.7.0)
CREATE TABLE recent_connections (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    profile_id TEXT NOT NULL,
    connected_at TEXT NOT NULL,  -- ISO 8601 timestamp
    FOREIGN KEY (profile_id) REFERENCES profiles(id) ON DELETE CASCADE
);

CREATE INDEX idx_recent_connections_profile_id ON recent_connections(profile_id);
CREATE INDEX idx_recent_connections_connected_at ON recent_connections(connected_at DESC);

-- Track active embedded terminal sessions (for multi-tab support)
CREATE TABLE active_sessions (
    id TEXT PRIMARY KEY,           -- Session UUID
    profile_id TEXT NOT NULL,
    tab_id TEXT NOT NULL,          -- Frontend tab ID
    started_at TEXT NOT NULL,
    last_activity_at TEXT NOT NULL,
    FOREIGN KEY (profile_id) REFERENCES profiles(id) ON DELETE CASCADE
);

-- Centralized settings storage (better than localStorage alone)
CREATE TABLE user_settings (
    key TEXT PRIMARY KEY,
    value TEXT NOT NULL,           -- JSON-serialized
    updated_at TEXT NOT NULL
);
```

**Note:** Connection history with full metadata (exit status, duration, error messages, logs) **deferred to v0.7.0**.

## Backend (Rust) Changes

### New File: `src-tauri/src/pty_manager.rs`

Separate module for PTY/SSH session management using `russh` crate.

**Responsibilities:**
- SSH connection establishment (async with russh)
- PTY spawning and management
- I/O forwarding to frontend via Tauri events
- Session lifecycle (create, resize, close)
- Multiple concurrent sessions support

**Key structures:**
```rust
pub struct PtyManager {
    sessions: Arc<Mutex<HashMap<String, SessionHandle>>>,
}

struct SessionHandle {
    ssh_client: Arc<russh::client::Handle<SshHandler>>,
    channel: Arc<Mutex<russh::Channel<Msg>>>,
    reader_task: tokio::task::JoinHandle<()>,
    tab_id: String,
}
```

**Update `connectToProfile()`:**
```javascript
async function connectToProfile(id) {
    const profile = profiles.find(p => p.id === id);
    if (!profile) return;

    const terminalPreference = localStorage.getItem('terminalPreference') || 'default';

    if (terminalPreference === 'embedded') {
        // Check if terminal modal already open
        if (!document.getElementById('terminal-modal').classList.contains('hidden')) {
            // Add new tab to existing modal
            await openEmbeddedTerminal(id);
        } else {
            // Open modal with first tab
            await openEmbeddedTerminal(id);
        }

        // Record connection (backend handles deduplication)
        // Backend will UPDATE timestamp if profile exists, INSERT if new
    } else {
        // External terminal flow
        await invoke('connect_ssh', { profileId: id, ... });
    }

    // Reload recent connections
    setTimeout(() => loadRecentConnections(), 500);
}
```

## Multi-Tab Terminal Behavior

### Opening Tabs
1. **First connection:** Opens terminal modal with 1 tab
2. **Subsequent connections (modal open):** Adds new tab to existing modal
3. **"New Tab" button:** Shows profile selector, opens in new tab
4. **Each tab:** Independent SSH session, separate PTY process

### Tab Navigation
- **Click tab:** Switch to that tab
- **Cmd/Ctrl+Tab:** Cycle to next tab
- **Cmd/Ctrl+Shift+Tab:** Cycle to previous tab
- **Click X on tab:** Close that specific tab
- **Cmd/Ctrl+W:** Close current tab

### Modal Close Behavior
- **"Close All" button:** Closes all tabs and modal
- **ESC key:** Closes current tab (or modal if last tab)
- **Last tab closed:** Automatically closes modal

### Session Tracking
- Tabs tracked in `active_sessions` database table
- Survive app minimize (modal closes but sessions tracked)
- **Do NOT survive app restart** (clean slate on launch)
- Tab IDs persist for reconnection after minimize

### Concurrency
- Multiple SSH sessions run in parallel
- Each tab = isolated PTY process
- Independent input/output streams
- No cross-tab interference

## UX Flow Examples

### Opening Embedded Terminal (Multi-Tab)
```
User clicks "Connect" on Profile A
  → Check terminalPreference === "embedded"
  → Terminal modal closed → Open modal with Tab 1 (Profile A)
  → invoke('start_embedded_ssh_session', { profileId: A, tabId: uuid1 })
  → Backend: russh connects, creates PTY, returns sessionId
  → Frontend: Create xterm instance, wire up events
  → SSH session running in Tab 1

User clicks "Connect" on Profile B (modal still open)
  → Modal open → Create Tab 2 in existing modal
  → invoke('start_embedded_ssh_session', { profileId: B, tabId: uuid2 })
  → New xterm instance in Tab 2
  → Now 2 concurrent SSH sessions running

User clicks "New Tab" button
  → Show profile selector modal
  → User selects Profile C
  → Create Tab 3 with Profile C
  → 3 concurrent sessions

User closes Tab 2
  → invoke('close_embedded_session', { tabId: uuid2 })
  → Backend kills SSH session for Tab 2
  → Frontend: cleanup xterm, remove tab from UI
  → Tabs 1 and 3 still running
```

### Using Recent Connections with Deduplication
```
Initial state: No recent connections

User connects to "Production Server"
  → Backend: INSERT into recent_connections (profile_id: prod, connected_at: now)
  → Recent bar shows: [Production Server]

User connects to "Dev Server"
  → Backend: INSERT (profile_id: dev, connected_at: now)
  → Recent bar shows: [Dev Server, Production Server]

User connects to "Production Server" again
  → Backend: Check if prod exists in recent_connections
  → EXISTS → UPDATE connected_at = now (moves to top)
  → Recent bar shows: [Production Server, Dev Server]  (no duplicate)

User connects to 3 more servers (Staging, QA, Backup)
  → Recent bar (limit=5) shows: [Backup, QA, Staging, Production, Dev]

User sets limit to 3 in settings
  → Recent bar shows: [Backup, QA, Staging]  (only 3 most recent)

User sets limit to 0
  → Recent bar hidden entirely
```

## Security Considerations

1. **Input Validation:** All Tauri commands validate inputs
2. **SSH Security:** russh handles SSH protocol securely
3. **PTY Isolation:** Each terminal session has isolated PTY
4. **Session Cleanup:** Proper cleanup on tab close/app exit
5. **Password Handling:** Never log passwords anywhere
6. **XSS Prevention:** Use `escapeHtml()` for all dynamic content
7. **Database:** Parameterized queries, foreign key constraints
8. **Base64 Encoding:** Terminal data safely transmitted

## Migration & Compatibility

### v0.5.2 → v0.6.0 Upgrade

1. **Database migration runs automatically on first launch**
   - `schema_version` table created
   - Migration 1: Create `recent_connections` table
   - Migration 2: Create `active_sessions` table
   - Migration 3: Create `user_settings` table
   - All existing profiles preserved

2. **Settings migration**
   - Terminal preference migrates from localStorage to `user_settings` table
   - Recent connections limit: defaults to 5
   - Keyboard shortcuts: enabled by default

3. **Automatic backup created before migration**
   - Backup location: `~/Documents/ssh-profile-manager-backups/`
   - Includes: Database file + current settings JSON

4. **First-launch tutorial** (dismissible)
   - Highlights new features: tabs, shortcuts, customization

### Connection History/Logs Feature

**What was deferred:**
- Full `connection_history` table with metadata:
  - Profile snapshot (name, host, username, port)
  - Connection timestamps (connected_at, disconnected_at)
  - Duration tracking (duration_seconds)
  - Exit status (success, error, killed)
  - Exit code and error messages
  - Terminal type (external vs embedded)
- Connection History modal with:
  - Filter by profile, status, date range
  - Pagination (50 per page)
  - "Reconnect" button from history
  - Export history to CSV

**Why deferred:**
- Simplifies v0.6.0 scope
- Recent connections (last 5-20) covers 80% use case
- Full history is more complex (storage, UI, filters)
- Better to perfect core terminal functionality first

**Current workaround:**
- `recent_connections` table provides quick access to recent
- Users can still see last N connections (configurable)

## Summary

1. **Keyboard Shortcuts** - Power user navigation with comprehensive shortcuts

3. **Embedded Terminal (Multi-Tab)** - Full-featured in-app terminal with russh, multiple concurrent sessions, tab management

- Database migration system for future-proofing
- `user_settings` table for robust settings storage
- Separate `pty_manager.rs` module for clean code organization
- russh for better SSH control and async architecture
- Multi-tab support from day one

**Deferred to v0.7.0:**
- Full connection history with metadata, filters, and detailed tracking

All features maintain existing architecture patterns, follow security best practices, and include comprehensive testing strategies. Total implementation time: **15-18 days**.
